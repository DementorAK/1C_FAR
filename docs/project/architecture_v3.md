# Архитектура мультиплатформенного плагина v3: Static Multi-Feature (FAR 3 + far2l + far2m)

## 1. Введение и предыстория перехода (V2 → V3)

В Архитектуре v2 (Dual-API) предполагалось разделение плагина на две основные ветки через Cargo-фичи: `far3` (Windows) и единую фичу `far2` для Unix-подобных систем (`far2l` и `far2m`). Также планировалось использование динамического runtime-враппера (`far_api.rs`) для сглаживания различий между версиями FAR 2 API.

Однако в процессе реализации Фазы 6 и перехода к Фазе 7 были выявлены критические ограничения:

1. **Несовместимость ABI/API:** Проекты `far2l` и `far2m`, хотя и унаследовали общие корни от FAR 2.0 API, развиваются независимо. Различия наблюдаются не только между самими портами, но и между версиями внутри этих портов. Различия в именовании путей конфигурации, структуре окружения и требованиях к сборке делают компиляцию под единую фичу `far2` нестабильной.
2. **Проблемы динамического враппера:** Попытка динамического связывания через враппер во время выполнения усложняет отладку и увеличивает риск падения (`SIGSEGV`) из-за жестких требований к выравниванию структур (`packed(2)`) на Linux. Динамический враппер не обеспечивает строгой типобезопасности при таких платформенных отличиях.

В **Архитектуре V3** было принято решение:

* Полностью отказаться от динамического враппера (`far_api.rs`) в пользу **статического связывания на этапе компиляции**.
* Разделить фичу `far2` на две независимые фичи: `far2l` и `far2m`.
* Фиксировать структуры данных и SDK для каждого целевого API отдельно.

## 2. Сводная матрица платформ и целевых API

В Архитектуре V3 поддерживаются 3 независимые сборочные цели:

| Характеристика | FAR Manager 3 (Windows) | far2l (Linux/macOS) | far2m (Linux/macOS/BSD) |
|---|---|---|---|
| **Cargo Feature** | `far3` (по умолчанию) | `far2l` | `far2m` |
| **Целевая ОС** | Windows | Linux / macOS | Linux / macOS / BSD |
| **Локальный SDK** | `docs/FAR3_PluginSDK` | `docs/FAR2L_PluginSDK` | `docs/FAR2M_PluginSDK` |
| **Путь к настройкам** | SQLite через `SettingsControl` | INI-файл в `~/.config/far2l/` | INI-файл в рабочем каталоге плагина |

## 3. Новая структура модулей плагина

Каждая платформа получила полностью изолированное подпространство имен внутри слоя `far/`. Это исключает пересечение несовместимых типов и макетов памяти:

```
src/
├── lib.rs                          -- Точка входа, условный экспорт API-функций
├── far/                            -- СЛОЙ 1: Взаимодействие с Far Manager
│   ├── mod.rs                      -- Объединяет платформы, хранит глобальное состояние
│   ├── traits.rs                   -- Дизайн-абстракция FarHost
│   ├── string_utils.rs             -- Преобразования строк
│   ├── ui.rs                       -- Точка монтирования UI под фичу
│   ├── lang.rs                     -- Локализация и сообщения
│   ├── settings.rs                 -- Настройки: load/save (адаптировано под фичи)
│   ├── panels.rs                   -- Бизнес-логика виртуальных панелей
│   │
│   ├── far3/                       -- Изолированный код FAR 3 (Windows)
│   │   ├── mod.rs                  -- Реэкспорты FAR3
│   │   ├── api.rs                  -- Типы и биндинги FAR 3 SDK
│   │   ├── exports.rs              -- C-экспорты FAR 3 (`#[no_mangle]`)
│   │   └── ui.rs                   -- Реализация диалогов под FAR 3
│   │
│   ├── far2l/                      -- Изолированный код far2l (Linux)
│   │   ├── mod.rs                  -- Реэкспорты far2l
│   │   ├── api.rs                  -- Типы и биндинги far2l SDK
│   │   ├── exports.rs              -- C-экспорты far2l (`#[no_mangle]`)
│   │   └── ui.rs                   -- Реализация диалогов под far2l
│   │
│   └── far2m/                      -- Изолированный код far2m (Linux)
│       ├── mod.rs                  -- Реэкспорты far2m
│       ├── api.rs                  -- Типы и биндинги far2m SDK
│       ├── exports.rs              -- C-экспорты far2m (`#[no_mangle]`)
│       └── ui.rs                   -- Реализация диалогов под far2m
│
├── v8/                             -- СЛОЙ 2: Разбор контейнеров 1С
└── base/                           -- СЛОЙ 3: Базовый парсинг и I/O
```

## 4. Механизм условного экспорта (lib.rs)

Файл `src/lib.rs` служит единой точкой сборки библиотеки. В зависимости от активной Cargo-фичи в таблицу экспорта готового `.dll`/`.so` файла попадают только соответствующие функции:

```rust
pub mod base;
pub mod far;
pub mod v8;

// Экспортируем функции только для активной фичи на этапе компиляции
#[cfg(feature = "far3")]
pub use far::far3::exports::*;

#[cfg(feature = "far2l")]
pub use far::far2l::exports::*;

#[cfg(feature = "far2m")]
pub use far::far2m::exports::*;
```

## 5. Хранение настроек (settings.rs)

В Архитектуре V3 логика сохранения и загрузки параметров строго разделена:

1. **Windows (`far3`):** Настройки сохраняются в системную базу данных SQLite плагина с помощью API-функций `SettingsControl` хоста FAR Manager.
2. **Linux (`far2l`/`far2m`):** Поскольку API для работы с базой настроек в FAR 2 отсутствует, настройки сохраняются в стандартный текстовый файл формата INI. Путь к конфигурационному файлу для каждого порта свой:
   * **для far2l:** `~/.config/far2l/plugins/Far1C/config.ini` (согласно стандартам XDG Base Directory)
   * **для far2m:** `config.ini` создается непосредственно в рабочем каталоге самого плагина (рядом с исполняемым файлом `.so`), так как `~/.config/far2m/` используется в порте преимущественно для других задач (например, дампов падений).

Инициализация пути к INI-файлу выполняется динамически в функции `SetStartupInfoW` соответствующего экспорта:
- В `far2l` с использованием переменной окружения `HOME` / `XDG_CONFIG_HOME`.
- В `far2m` путь рассчитывается от `ModuleName` загруженного плагина.

## 6. Сборочные инструкции для разработчиков

Сборка конкретной платформы осуществляется явным переопределением фич и целевой архитектуры компилятора:

```powershell
# 1. Сборка для Windows (FAR Manager 3)
cargo build --release --features far3 --no-default-features

# 2. Сборка для Linux (far2l)
cargo build --release --features far2l --no-default-features --target x86_64-unknown-linux-gnu

# 3. Сборка для Linux (far2m)
cargo build --release --features far2m --no-default-features --target x86_64-unknown-linux-gnu
```
