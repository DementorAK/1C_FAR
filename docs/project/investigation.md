# Протоколы расхождений парсинга артефактов (Фаза 9.2)

> Документ фиксирует расхождения между представлением артефактов плагином far1c и эталонной выгрузкой средствами платформы 1С:Предприятие 8.
>
> **Фаза 9.2** — обновление после исправлений: улучшено именование корневых файлов, создание каталогов объектов, генерация XML вместо RawData/CDATA.

---

## Методика

Для каждого тестового артефакта:
1. Выгрузка эталонной структуры из Конфигуратора 1С в файлы → каталог `investigation/<artifact>/1c/`
2. Копирование представления плагина (из виртуальной панели, стиль Configurator) → каталог `investigation/<artifact>/far/`
3. Сравнение структуры, файлов, содержимого

**Условные обозначения:**
- 🔴 **Критическое** — элемент отсутствует или содержит неверные данные
- 🟡 **Существенное** — элемент отображается некорректно, но артефакт формально читаем
- 🟢 **Косметическое** — незначительное расхождение в форматировании
- ✅ **Совпадает** — расхождений не обнаружено
- 🔷 **Исправлено** — проблема была в фазе 9.1, но устранена в текущей версии

### S-001: Неполный корневой XML (урезанные свойства) 🟡

**Все артефакты:** все

| Параметр | Эталон (1С) | Плагин (far1c) |
|----------|-------------|----------------|
| Формат | Полноценный XML с 18 xmlns-декларациями, семантические теги | XML с 1-2 xmlns-декларациями |
| Namespaces | `v8`, `xr`, `cfg`, `xs`, `xsi`, `app`, `pal` и др. | Только `xmlns="http://v8.1c.ru/8.3/MDClasses"` (+ `xr` на вложенных) |
| Содержимое | Все элементы: `<Properties>`, `<ChildObjects>`, `<InternalInfo>` | Часть элементов: `<Properties>` без `<DefaultForm>`, `<AuxiliaryForm>`, `<ChildObjects/>` |
| `<Comment/>` | `<Comment/>` (самозакрывающийся) | `<Comment></Comment>` (полный) |

**Статус:** 🔴→🟡 **Улучшено**. Ранее был `<RawData><![CDATA[...]]></RawData>`, теперь генерируется полноценный XML, но с урезанным набором элементов. Для EPF/ERF основная структура корректна (UUID, Name, Synonym, InternalInfo), отсутствуют `<DefaultForm>`, `<AuxiliaryForm>`, `<ChildObjects/>`.

## Классификация корневых причин

### 1. Неполная трансляция скобочного формата → XML Конфигуратора

**Затронуто:** Все артефакты (S-001, S-004, S-005, S-007)

Для основных объектов (ExternalDataProcessor, ExternalReport) реализована генерация XML, но отсутствуют элементы `<DefaultForm>`, `<AuxiliaryForm>`, `<ChildObjects/>`, полный набор namespace-деклараций.

Для форм, шаблонов, ролей, языков трансляция в XML не реализована — используется RawData/CDATA.

### 2. Неполный разбор вложенных контейнеров CF/CFE

**Затронуто:** `1Cv8.cf` (CF-003), `Ext1.cfe` (S-006, CFE-001)

VFS-builder не раскрывает вложенные объекты метаданных (DataProcessors, Reports) конфигурации. Корневые объекты (языки, роли) отображаются как UUID-файлы.

### 3. Потеря модуля формы (Module.bsl)

**Затронуто:** `Ext1_cfe` (CFE-002)

Форма хранится как единый блок, из которого нужно извлекать:
- `Form.xml` — описание макета формы (элементы, свойства)
- `Module.bsl` — код модуля формы

Плагин формирует Form.xml как RawData/CDATA со всем содержимым блока, Module.bsl не создаётся.

### 4. Защищённые модули не извлекались 🔷 **ИСПРАВЛЕНО**

**Затронуто:** `protected_epf` (P-001)

**Причины (было две):**

1. UUID защищённого модуля не находился по жёсткому пути `[3,1,1,3,1,1,2]` — для защищённого EPF модуль существует только как `.0`-row (body) без соответствующего header-row (`{uuid}` без `.0`). Добавлен fallback, ищущий `.0`-row без header-row.

2. Данные модуля начинались с `0x7FFFFFFF` (V8 container SIG), что заставляло `extract_module_text` пытаться открыть их как контейнер. При отсутствии `"text"`-строки функция возвращала `None`. Исправлено: при отсутствии `"text"`-строки данные теперь трактуются как сырые (raw).

### 5. UUID-файлы для корневых объектов CF/CFE

**Затронуто:** `1Cv8_cf`, `Ext1_cfe` (S-006)

Объекты метаданных на корневом уровне конфигурации (Language, Role) не распознаются как именованные и отображаются с UUID-именами.
